# Demo 演示脚本（群里实操录屏用）

## 场景一：直接下单（基础能力热身）
```
你：救命我快困死了，来一杯生椰拿铁续命，冰的
（等机器人报价）
你：确认下单，公司的钱不花白不花
```
传播点：开场用"续命"这种打工人共鸣感拉近距离，最后一句自带调侃老板买单的梗。
截图重点：报价消息 + 真实支付二维码。

## 场景二：DIY 专家模式 → 匹配成功 → 转下单（核心创新点）
```
你：帮我设计一杯咖啡，我今天心情很好，想要清爽一点的
（等机器人给选项）
你：果香清亮，但别太甜，我怕齁
（等机器人继续问或直接收敛）
你：冰的，不加糖
（机器人应推荐一个接近商品）
你：诶还挺懂我的，多少钱
你：确认下单
```
传播点："诶还挺懂我的"这句是天然的用户真实反应，展示 AI 专家不是硬凑答案。
截图重点："XX 挺接近，要不要试试"那条 + 支付二维码。

## 场景三：DIY 专家模式 → 匹配不到 → 沉淀许愿池（数据资产价值）
```
你：我想要一杯西瓜汁加一点点咖啡的那种，夏天限定既视感
你：要清爽果香，咖啡感很淡，就加个提神的意思
你：冰的，别太甜，齁人劝退
```
预期回复"这杯现在做不出来，我记下来了"——配合 `data/wishlist.jsonl` 里对应记录一起放，证明不是嘴上说说。不用真下单。
传播点："夏天限定既视感"这种梗化描述，配上机器人"没有但记下来了"的反差，很适合截图配文"申请上新，评论区扣1"。

## 场景四：多人多杯合并下单（团队场景，对应痛点一）
```
你：领导仨人正在开会，说想喝点东西提提神，但他们仨都不喝咖啡，这可咋整
（等机器人给选项）
你：老板说要茶香清爽，副总要果香甜美，总监要奶香浓郁，一人来一杯
（等机器人继续问或收敛）
你：全部冰的，都不加糖，开会呢别齁着领导
你：好嘞都要，总共多少钱
你：确认下单，摸鱼一时爽，点单一直爽
```
传播点："这可咋整""摸鱼一时爽点单一直爽"这种打工人黑话，配合三杯一次合并下单的截图，很有传播基因。
截图重点：一次 `previewOrder` 出现总价（不是三笔分开）+ 一张支付二维码（不是三张）。

## 场景五：老板生日请客，按每位员工的口味记忆各点一杯（口味记忆 + 团队场景）
前提：这几位员工之前已经用 bot 点过单（`tastes.js` 里有历史记录），或者先跑一遍场景一/四攒点历史数据再录这个。
```
你：今天我生日，请公司三位兄弟每人喝一杯他们平时最爱喝的，我请客，门店还是西大望路平乐园店
（机器人应参考历史订单记忆，报出每个人的常点饮品）
你：好家伙还记得住，都要，多少钱
你：确认下单，生日快乐我自己
```
传播点："好家伙还记得住"是最直击"AI 员工有记忆"这个卖点的真实反应，"生日快乐我自己"自带自嘲喜感，适合做成表情包式截图。
截图重点：机器人主动提到"XX 之前点过 YY"这种引用历史口味的措辞 + 合并总价 + 支付二维码。

## 录制建议
- 场景二、四、五是核心卖点，优先保证录全
- 场景三不用真下单，聊到"记下来了"那句就停
- 场景一最简单，可当开场热身，信息量有限可以不录

## 待确认/待实现
- 场景五依赖的"口味记忆"目前只在**同一个下单模式会话内**注入最近历史（`server.js` 的 `handleOrderTurn`），还没有专门测试过"跨会话、跨多人分别记忆"这种更复杂的场景，明天实测前建议先验证一遍这条链路是否真的按预期工作，不确定的话现场录制可能翻车。
- "预定/定时批量下单"这个功能（第一节痛点四提到的）**目前还没有实现**，只是方案设计里的规划能力，不能安排进这次录屏的演示脚本里，如果误录会跟"演示了什么"和"方案里写了什么"对不上。
